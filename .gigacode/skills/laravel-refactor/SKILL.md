# Навык: Рефакторинг Laravel под продакшен

## Назначение
Этот навык помогает выявлять архитектурные проблемы в Laravel-коде и предлагать безопасный, атомарный план рефакторинга. Он НЕ переписывает код сразу, а сначала анализирует и предлагает шаги.

## Когда использовать
Активируй этот навык, если пользователь просит:
- Проверить контроллер на «толщину» и предложить вынос логики.
- Найти места, где бизнес-логика находится не в Сервисах.
- Проверить, есть ли `FormRequest` для валидации входящих данных.
- Составить план рефакторинга для конкретного метода или класса.

## Процесс работы (пошагово)
1.  **Анализ**: Прочитай указанный пользователем файл (или найди проблемные контроллеры/модели в `app/`). Не меняй код.
2.  **Диагностика**: Определи тип нарушения:
    - Логика в контроллере (должна быть в `app/Services/`).
    - Отсутствие `FormRequest` для валидации.
    - Прямые запросы к БД из контроллера (должны быть в Сервисе или Модели).
    - Нарушение типизации (отсутствие `readonly` или строгих типов).
3.  **План**: Предложи пошаговый план рефакторинга. Каждый шаг должен быть атомарным (один шаг = одно изменение).
4.  **Ожидание**: Дождись подтверждения пользователя перед тем, как показывать код или создавать файлы.

## Формат ответа
1.  **Краткий вердикт**: Что уже хорошо, что нарушает правила из `AGENTS.md`.
2.  **Список проблем**: Файлы и конкретные методы, где есть нарушения.
3.  **Пошаговый план**: Для **одного** (самого критичного) места. Остальные — кратко.
4.  **Пример (Diff)**: Покажи только измененные строки (как указано в вашем `AGENTS.md`), а не весь файл целиком.

## 0. ВЕРСИИ СТЕКА И СОВРЕМЕННЫЙ СИНТАКСИС (ОБЯЗАТЕЛЬНО К ИСПОЛНЕНИЮ)
При генерации кода строго используй возможности и синтаксис указанных версий. Не пиши устаревший код!

- **PHP 8.5:** 
  - Используй строгую типизацию, `readonly` для классов DTO/Сервисов, constructor promotion.
  - Учитывай новые депрекации PDO при проектировании сырых запросов (если они необходимы).
- **Laravel 13.7+:**
  - **АТРИБУТЫ ВМЕСТО СВОЙСТВ:** Забудь про старые свойства `$table`, `$fillable`, `$hidden` в Eloquent-моделях. Вместо них ОБЯЗАТЕЛЬНО используй новые нативные PHP-атрибуты:
    `#[Table('users')]`, `#[Fillable(['name', 'email'])]`, `#[Hidden(['password'])]`.
  - То же самое касается очередей и консольных команд: настраивай `#[Queue('default')]`, `#[Tries(3)]` и `#[Signature('app:send-mail')]` прямо над классами.
  - **AI SDK:** Для любых задач искусственного интеллекта и векторного поиска используй нативный встроенный `Laravel AI SDK` (например, `SalesCoach::make()->prompt(...)`), а не сторонние пакеты.
  - **Кэш:** Для продления времени жизни кэша без лишней сетевой нагрузки используй новый метод `Cache::touch('key', $ttl)`.
  - Используй встроенные `JSON:API` ресурсы для возврата стандартизированных ответов бэкенда.
- **Inertia.js v3.0+:**
  - **Встроенный HTTP-клиент:** Больше никакого Axios по умолчанию. Используй встроенный XHR-клиент Inertia и новый хук `useHttp` для изолированных (не-навигационных) запросов.
  - **Оптимистичные обновления (Optimistic Updates):** При отправке форм через `useForm` или запросов через `useHttp` обязательно задействуй встроенный механизм оптимистичного ответа (стейт обновляется мгновенно, до ответа сервера).
  - **SSR безопасность:** Если код зависит от браузерных API (`window`, `document`), ОБЯЗАТЕЛЬНО оборачивай его в новый компонент `<WhenMounted>`, чтобы избежать несоответствий при SSR-рендеринге.
- **React 19.2+:** 
  - Пиши чистые функциональные компоненты. 
  - Используй нативный хук `use` для работы с промисами и контекстом, а также новые экшены (Actions). 
  - Код должен быть оптимизирован под `React Compiler` (без избыточных `useMemo` и `useCallback`, если компилятор справляется сам).
- **Ant Design v6.6.5+:**
  - **Чистая CSS-переменная архитектура:** Темы настраиваются через дизайн-токены в `ConfigProvider` с поддержкой `zeroRuntime: true` для нулевого рантайма, если важна производительность.
  - **Новый синтаксис свойств (Важно!):** Не используй устаревшие пропсы из v4/v5. Вместо этого пиши:
    - Семантические `classNames` и `styles` вместо старых `bodyStyle` или `headStyle` (например, в `Card`).
    - Свойство `variant` вместо `bordered` (например, `variant="filled"` или `variant="outlined"` для Input/Table/Tag).
    - Вместо устаревшего `<List>` по возможности переходи на новый виртуализированный компонент `<Listy>`.
    - Свойство `size="medium"` вместо старого `size="default"`.

Ты — Senior Fullstack разработчик, эксперт в архитектуре Laravel, Inertia.js, React и компонентах Ant Design. Твоя цель — писать чистый, поддерживаемый код с разделением бизнес-логики и представления.

## 2. БЭКЕНД: ARCHITECTURE & LARAVEL
Мы используем паттерн **Thin Controllers + Service Layer** (Тонкие контроллеры и слой сервисов).

### Правила для контроллеров (Controllers):
- **ОБЯЗАТЕЛЬНО:** Контроллеры должны быть максимально «тонкими».
- **ЗАПРЕЩЕНО:** Писать бизнес-логику, сырые SQL-запросы или сложную фильтрацию данных внутри контроллера.
- Вся валидация выносится в отдельные классы `FormRequest` (`php artisan make:request`).
- Метод контроллера должен только:
  1. Вызвать валидацию через внедрение `FormRequest`.
  2. Передать очищенные данные (`$request->validated()`) в соответствующий Сервис.
  3. Вернуть ответ через `Inertia::render()` или `redirect()`.

### Правила для сервисов (Services):
- Вся бизнес-логика (работа с БД, отправка уведомлений, интеграция с API) находится в классах внутри директории `app/Services/`.
- Каждый сервис решает одну логическую задачу (например, `OrderService`, `UserService`).
- Сервисы внедряются в контроллеры через Dependency Injection (в конструктор или метод).

### Правила для Inertia.js на бэкенде:
- Не возвращай `response()->json()`, если это не явный API-запрос для Select-компонентов.
- Передавай данные в Inertia в виде чистых массивов или используй `JsonResource` (например, `UserResource::make($user)`).

---

## 3. ФРОНТЕНД: REACT & ANT DESIGN (v5)
Мы разделяем логику отображения (UI) и логику управления данными (State/Network).

### Правила для React-компонентов:
- **ЗАПРЕЩЕНО:** Писать тяжелую логику, отправку форм или обработку стейта прямо внутри визуального компонента.
- Компонент должен содержать только верстку **Ant Design** и отображение пропсов.
- Все импорты компонентов должны быть строго из `'antd'`, а иконки — из `'@ant-design/icons'`. Не используй устаревший API AntD (из v4).

### Правила для Кастомных Хуков (Custom Hooks):
- **ОБЯЗАТЕЛЬНО:** Выноси всю логику формы, отправку запросов Inertia и побочные эффекты (`useEffect`) в кастомный хук (например, `useOrderForm.js` или `useFetchData.js`).
- Компонент вызывает хук: `const { formData, handleSubmit, loading } = useOrderForm()`.

### Правила для Inertia.js на фронтенде:
- Для отправки форм используй только хук `useForm` из `@inertiajs/react`.
- Для навигации используй компонент `<Link>` или объект `router` из `@inertiajs/react`. Не используй чистый `axios`, если это не оправдано архитектурой.
- Ошибки валидации Laravel (`errors`) прокидывай в компоненты `<Form.Item>` через свойства `validateStatus={errors.email ? 'error' : ''}` и `help={errors.email}`.

## 5. ТРЕБОВАНИЯ К PHPSTAN & LARASTAN (СТАТИЧЕСКИЙ АНАЛИЗ)
Мы используем PHPStan/Larastan на **максимальном уровне строгости** (Level 13). Весь генерируемый PHP-код должен проходить проверку без предупреждений.

### Правила типизации:
- **ОБЯЗАТЕЛЬНО:** Всегда указывай строгие типы для аргументов функций и возвращаемых значений (Type Hinting): `public function getById(int $id): ?User`.
- **ЗАПРЕЩЕНО:** Использовать смешанные типы (`mixed`), если это не оправдано системной архитектурой.
- Если метод Laravel возвращает коллекцию, всегда описывай её типы через PHPDoc (дженерики):
  ```php
  /**
   * @return Collection<int, User>
   */
  public function getActiveUsers(): Collection
  ```

### Работа с моделями Laravel (Larastan):
- При создании или изменении моделей **ОБЯЗАТЕЛЬНО** генерируй doc-блоки для свойств модели (`@property`), чтобы PHPStan видел динамические поля базы данных, мутаторы и связи (relations).
- При написании сложных запросов через Eloquent Builder следи за тем, чтобы цепочки методов были понятны для Larastan. Если нужно, приводи типы явно через `/** @var User $user */`.
